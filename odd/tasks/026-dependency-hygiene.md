# 026 - Higiene de dependencias y vulnerabilidades

Objetivo: eliminar vulnerabilidades reportadas y dejar apps/packages/frameworks en lo ultimo estable compatible.
Branch: `chore/026-dependency-hygiene` (crear desde `main`). Estrategia: `ask-on-risk`. Runner: `npm audit`, `npm outdated`, `turbo run build/lint/test`.

## Specs

- S1: "revisemos porque en Github dice que tenemos muchas vulnerabilidades" — triage: comparar GitHub Dependabot vs `npm audit` local fresco y `audit.txt` existente.
- S2: "pueden ser de paguetes... quiero imaginar" — confirmar si el origen son dependencias directas o transitivas y documentarlo por unidad.
- S3: "mantengamos TODOS paquetes y Frameworks siempre lo mas actualizado posible" — actualizar por unidad (apps, packages, root) a lo ultimo estable compatible; los saltos major con breaking changes se proponen por separado, no se fuerzan con `--force` sin aprobacion.
- S4: "empezamos una por una de las apps, packages, etc" — trabajo unidad por unidad, con verificacion (`audit` + `build/lint/test` del area) antes de pasar a la siguiente.
